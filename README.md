# Workshop Booking System — NestJS

Учебный проект для домашнего задания по модулю **«Разработка на NestJS»**.  
Система позволяет пользователям просматривать мастер-классы, регистрироваться, входить в систему, создавать бронирования и смотреть свои брони. Администратор может управлять мастер-классами.

## Стек

- TypeScript
- NestJS
- TypeORM
- SQLite-compatible sql.js
- JWT
- class-validator
- Docker
- Postman / Newman

## Что реализовано

- регистрация пользователя;
- вход пользователя с выдачей JWT-токена;
- роли `USER` и `ADMIN`;
- первый зарегистрированный пользователь автоматически получает роль `ADMIN`;
- публичный просмотр списка мастер-классов;
- публичный просмотр одного мастер-класса;
- CRUD мастер-классов только для администратора;
- создание бронирования только для авторизованного пользователя;
- просмотр только своих бронирований;
- отмена своего бронирования;
- запрет повторного бронирования одного мастер-класса одним пользователем;
- проверка вместимости мастер-класса;
- запрет записи на прошедшие мастер-классы;
- DTO и автоматическая валидация входящих данных;
- ответы API не возвращают пароль или хеш пароля;
- связи `User -> Booking`, `Workshop -> Booking`;
- уникальное ограничение на пару `user + workshop`;
- `LEFT JOIN` / `QueryBuilder` для загрузки связанных данных без лишних запросов;
- Dockerfile и docker-compose;
- коллекция Postman с переменными и тестами кодов ответа.

## Быстрый запуск через Docker

```bash
docker compose up -d --build
```

Проверка:

```bash
curl http://localhost:3000/api/health
```

Ожидаемый ответ:

```json
{
  "status": "ok",
  "service": "workshop-booking-system"
}
```

## Локальный запуск без Docker

```bash
npm install
npm run start:dev
```

По умолчанию приложение доступно по адресу:

```text
http://localhost:3000/api
```

SQLite-compatible sql.js-файл создаётся автоматически в папке `data`.

## Важная логика ролей

Чтобы не добавлять отдельную ручную настройку администратора, реализовано простое правило:

> первый зарегистрированный пользователь получает роль `ADMIN`, все следующие пользователи получают роль `USER`.

Поэтому для проверки сначала зарегистрируйте администратора, затем обычного пользователя.

## Основные эндпоинты

### Auth

```http
POST /api/auth/register
POST /api/auth/login
```

Пример регистрации:

```json
{
  "email": "admin@example.com",
  "displayName": "Admin",
  "password": "password123"
}
```

Пример ответа:

```json
{
  "accessToken": "jwt-token",
  "user": {
    "id": "uuid",
    "email": "admin@example.com",
    "displayName": "Admin",
    "role": "ADMIN",
    "createdAt": "2026-05-26T10:00:00.000Z"
  }
}
```

### Workshops

Публичные:

```http
GET /api/workshops
GET /api/workshops/:id
```

Только для администратора:

```http
POST /api/workshops
PUT /api/workshops/:id
PATCH /api/workshops/:id
DELETE /api/workshops/:id
```

Пример создания мастер-класса:

```json
{
  "title": "Основы веб-разработки",
  "description": "Практический мастер-класс по созданию REST API.",
  "location": "Онлайн",
  "startsAt": "2026-12-20T12:00:00.000Z",
  "durationMinutes": 120,
  "capacity": 10
}
```

### Bookings

Только для авторизованного пользователя:

```http
GET /api/bookings
POST /api/bookings
DELETE /api/bookings/:id
```

Пример создания бронирования:

```json
{
  "workshopId": "uuid-мастер-класса"
}
```

## Авторизация в Postman

Для защищённых запросов нужно передавать заголовок:

```http
Authorization: Bearer <accessToken>
```

В готовой коллекции Postman токены сохраняются автоматически после регистрации/входа.

## Postman-коллекция

Файл коллекции:

```text
postman/workshop-booking-system.postman_collection.json
```

Коллекция покрывает:

- health-check;
- регистрацию администратора;
- регистрацию обычного пользователя;
- вход администратора;
- вход пользователя;
- создание мастер-класса администратором;
- публичный список мастер-классов;
- публичную карточку мастер-класса;
- создание бронирования пользователем;
- просмотр своих бронирований;
- проверку запрета дубля бронирования;
- проверку запрета создания мастер-класса обычным пользователем;
- отмену бронирования.

Запуск коллекции через Newman:

```bash
npm run test:postman
```

## Примечание по Windows

В проекте используется `sql.js`, а не нативный пакет `sqlite3`, чтобы `npm install` на Windows не требовал установки Visual Studio Build Tools / C++ compiler. Файл базы сохраняется в `data/workshop_booking.sqlite`.
